# JLPT N1 真题库 + 机械化解题可行性研究

本仓库包含两部分：**12 场次 N1 真题的标准格式题库（1124 题，答案全部经原图验证）**，以及在此基础上做的一项实证研究——**能不能不靠日语能力、只靠规则和统计做对 JLPT N1**。

### 转写路线（重要）

题库由 **Claude Sonnet 直接读渲染后的试卷页图**产出，不走 OCR 文本。原因是实测的硬天花板：

- macOS Vision OCR **不输出下線信息**，`＜＞` 标记永远拿不到（問題4 每卷 24 处全缺）
- 小假名 `りょ→りよ` 在 3 种语言配置 × 2 种分辨率共 6 组测试中**全部失败且输出完全一致**
- JLPT 漢字読み題的干扰项**故意**混用大小假名（`しや`/`しゃ` 都是合法选项），所以正字法后处理会把对的改错（实测 63.6%→56.8%）

**答案表同样必须读原图**：OCR 抽答案表在読解部分会整体位移（2023-07 実測 66 题里错 13 题，
起因是 OCR 把「49番…56番 / 3 4 2 3 1 1 1」读成 8 个题号只跟 7 个答案）。
验证：agent 读的 2023-07 vs 人工逐格读原图 **96/96**；音A/B/C 规则全 12 套 **44/44**。

## 二、机械化解题可行性研究

### 一句话结论

| | 题/卷（共96） | 原始正确率 |
|---|---|---|
| 纯随机猜测 | 24.7 | 25.7% |
| **本项目全部工具（12 套全库实测）** | **49.2** | **51.3%** |
| 及格线（100/180）所需 | 56 | 约 58% |

**工具净贡献 +24.5 题/卷。缺口约 7 题必须由考生自身语言能力提供。**
12 套里只有 2025-12 一套折算过线（104/180），其余 70–94。

**JLPT N1 约一半可机械化，另一半不可以——不可机械化的部分恰好是"读懂 / 听懂"本身。**

完整研究记录见 **[FINDINGS.md](FINDINGS.md)**，全库评估见 **[EVALUATION.md](EVALUATION.md)**。

### 最有实用价值的三个发现

**1. 頻率带押题（p=0.0005）** — 被考过的句型在真实日语中的使用频次中位数为 214 次，从未被考的仅 36 次，差 6 倍。**按维基百科真实频次排序，精练前 30 条句型可覆盖 80% 的实际考点**，逐卷一致（67%–100%）。频率排名完全来自语料、与考卷无关，因此不需要任何真题就能得到备考优先级。

**2. 汉字音读规则是唯一零错误的路线** — 音A/送り仮名闸门、音B/禁止音训混搭、音C/漢語連濁限ん・っ后，全库 **44/44 = 100%**，净增 33 题。这三条能背进脑子。

**3. 三类题的干净分野** — 可推导的（8%）规则赢，约定俗成的（28%）语料赢，需要理解的（54%）两者皆输。

### 加新卷子的流程

1. 把 PDF 传到 `exams/raw/<场次>/`
2. 用 `fitz` 按 dpi=200 渲染需要的页为 PNG（言語知識 / 読解 / 聴解 / 答案表分开）
3. 交给 Sonnet agent 转写：**每页只读一次、只写一次、禁止回头重读**；提示词必带五条——
   禁止改错别字、禁止改假名大小写、选项编号照抄、**下線范围看准左右端**、括号统一全角 `（　）`
4. 答案表单独读原图 → `ocr/apply_answers.py`
5. `ocr/ingest.py <场次>` 入库（选项号位置归一化 + 合并答案 + 校验）
6. `ocr/check_format.py`（非标准重排卷加 `--loose`）
7. `solver/eval_all.py` 跑评估

详见 [ocr/README.md](ocr/README.md)。
